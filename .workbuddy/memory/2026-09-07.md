### 关键设计结论（后续开发以此为准）

- 9 张表：user / venue / court / activity / reservation / registration / post / comment / post_like，不增不减。
- reservation 是唯一场地占用账本：个人行 user_id 有值、活动行 activity_id 有值，两者至多一非空；活动行 user_id 必须为空（否则击穿「同用户最多 2 个重叠预约」规则）。
- 活动关联球场不落字段，由 reservation 行表达（一活动占 N 块场 = N 行）。
- 报名占人不占场：registration 一人一活动一条记录，取消=改 status；唯一键 (user_id, activity_id)。
- post_like 复合主键 (post_id, user_id)，不加代理主键；post 不加 like_count，点赞数用 COUNT 现算。
- 全表不做软删除；activity 永不物理删除（走状态）。
- MySQL 无排除约束，时段冲突/≤2 场上限/7 天窗口/4 小时取消窗口/状态级联/满员并发全部在 Service 层实现。
