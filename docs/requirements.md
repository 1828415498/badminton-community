# 需求分析

## 1. 项目背景

目标：为羽毛球爱好者提供一个集中交流、约球和活动组织的平台，降低新用户寻找球友和活动的成本，并帮助活动组织者管理活动。

## 2. 目标用户

- 大学生羽毛球爱好者
- 校外羽毛球爱好者
- 活动组织者（普通用户也可创建活动）
- 管理员

## 3. 核心痛点

1. 羽毛球爱好者尤其是新到一个环境的用户不容易找到球友和约球活动。
2. 活动信息容易分散，参与者不容易快速找到合适的活动。
3. 活动组织者需要管理场地、报名人数和活动状态。
4. 社区交流缺少集中载体。

## 4. MVP 范围

### 用户
- 注册
- 登录
- 退出
- 查看/修改个人资料

### 活动
- 创建打球活动
- 查看活动列表/详情
- 修改自己的活动
- 取消自己的活动
- 提交审核
- 管理员审核
- 活动发布/结束

### 场地
- 系统维护一个羽毛球馆及其球场资源
- 提前 7 个自然日开放预约
- 整点时间粒度
- 用户预约一个或多个球场
- 用户查询自己的预约
- 取消预约

### 报名
- 报名活动
- 取消报名
- 查看报名成员
- 人数上限与满员控制

### 社区
- 发帖
- 评论
- 点赞/取消点赞
- 管理员处理违规内容

## 5. 核心业务规则（当前版本）

1. 所有登录用户都可以创建打球活动。
2. 创建活动必须填写日期、开始时间、结束时间。
3. 一个活动可以对应多个具体球场。
4. 当前 V1 只管理一个羽毛球馆。
5. 场地提前 7 个自然日开放预约。
6. 预约采用整点时间粒度，可连续预约多个时间段。
7. 同一球场同一时间范围内不能存在冲突的有效预约。
8. 同一用户在重叠时间范围内最多同时预约两个球场。
9. 开场前至少 4 小时可以免费取消自己的预约。
10. 开场前不足 4 小时，普通用户不能自行取消预约。
11. 管理员可以在特殊情况下取消预约。
12. 活动需要管理员审核后才能正式发布。
13. 活动被驳回或取消后，应释放关联的有效场地预约。
14. 一个用户不能重复报名同一个活动。
15. 一个用户对同一帖子只能存在一次有效点赞。
16. V1 一个活动只包含一个连续的时间区间，但可以对应多个球场。
17. 场地提前 7 个自然日开放预约的规则，同样适用于活动占场：活动创建时锁定的球场时段也必须落在开放窗口内，避免通过创建活动绕过预约开放规则。

## 6. 非 MVP / 暂不实现

- 多羽毛球馆
- 即时聊天/私信
- 关注关系
- 推荐算法
- 支付
- 微服务拆分
- 复杂会员体系
